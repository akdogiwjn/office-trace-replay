# 规模扩大后，旧 OPM＋TLC 能覆盖多少热点函数？

## 主要判断

规模扩大后，Excel 014 和 PDF 037 的旧函数覆盖权重明显提高；Word 003 仅小幅提高，PPT 021 的图像处理缺口仍然突出。本批结果支持部分低覆盖与小输入下公共开销占比高有关，但它不能解释全部未覆盖热点。

这里的“覆盖”指新任务中的叶函数，在旧 OPM＋TLC 的完整已解析函数清单中出现过。按库文件名＋完整物理函数名精确匹配，包含旧清单低频函数。百分比以新任务完整 workflow ROI 的 cycles:u 样本 period 为分母；它是采样周期权重，不是总 CPU 时间，也不表示旧例覆盖了全部业务操作。未解析部分单列。

## 2. Word：固定开销下降，但 PNG 滤波仍是主要缺口

本任务先清理修订、评论、元数据和私人信息，再重建公开 DOCX，最后经 LibreOffice 转 PDF，由 pdftoppm 渲染 PNG。新增页数同时增加文档处理与预览生成工作。

| 任务 | pdftoppm 权重 | 未见 PNG 函数 | 未见 Python 函数 | 未见 LO 公共组件函数 |
|---|---|---|---|---|
| 003 | 51.54% | 9.05% | 6.82% | 5.62% |
| 003-u100 | 89.69% | 20.49% | 1.74% | 0.92% |
| 003-u500 | 89.42% | 22.12% | 2.65% | 1.14% |

- Python 未匹配函数从 6.82% 降至 2.65%，LibreOffice 公共组件从 5.62% 降至约 1.14%。这一变化与公共开销被摊薄的解释一致。
- 500 单元中 `png_write_find_filter` 单个函数约占 22.10%，记录的执行脚本为 pdftoppm。它为输出 PNG 选择行滤波方式，以利后续压缩；不是 Word 排版函数，也不是新出现了图片处理需求。旧 OPM 已有图片处理，但旧清单未观察到这个具体 libpng 函数。
- 100→500 单元时，该滤波函数从约 20.45% 升至 22.10%，字符串搜索函数 `ucs2lib__two_way` 从约 0.90% 升至 2.43%，抵消了其他开销的下降。其中大档约 2.42% 记录于 validate_public_packet_variant.py，主要属于校验器的字符串搜索，不能自动归为 Word 编辑专属机制。
- Word 参数化变体还采用了已核验的校验器优化（整段 XML 只转小写一次），父任务与变体间并非只改变输入体积；这部分变化不能全归因于规模。

## 3. PDF：覆盖提高，主要剩余缺口集中到 PNG 滤波

037 是 ReportLab 按业务数据绘制材料页、pypdf 写书签和元数据、pdftoppm 渲染 PNG。扩大的是实际绘制内容和页数，不是复制既有 PDF 页面；两档 seed PDF 字节相同不代表工作量相同。

| 任务 | pdftoppm 权重 | 未见 Python 函数 | 未见 PNG 函数 |
|---|---|---|---|
| 037 | 68.32% | 16.17% | 10.27% |
| 037-u5 | 91.04% | 3.43% | 12.24% |
| 037-u20 | 95.70% | 0.77% | 11.22% |

- 未见 Python 函数从 16.17% 降至 0.77%，旧函数覆盖从 72.77% 提高到 86.72%。这一方向支持“小输入会让解释器启动、源码解析等公共工作显得更突出”的解释。
- 大档仍有 13.28% 已解析函数未在旧清单出现，其中 `png_write_find_filter` 占 11.22%。剩余以少量字体、页面绘制和解释器函数为主；不能把整个差额称为全新 PDF 计算。
- 大档 `longest_match` 占约 66.04%，主要由 pdftoppm 执行，体现预览 PNG 的压缩。它已在旧 OPM／TLC 中出现，是旧两例能够覆盖的重要基础热点。

## 4. 与 Excel／PPT 规模实验合并看

- Excel 014：旧函数覆盖达到 91.82%，主要是大量 PDF 页面渲染与 PNG 压缩权重上升；不能据此说工作簿编辑本身占了这些周期。大档未见函数约 7.12%，PNG 滤波约 4.12%。
- PPT 021：大档仅覆盖 50.44%，仍有约 47.45% 已解析未匹配。ImageMagick 横纵向滤波、libjpeg 编码、LibreOffice 位图处理和 Poppler 子路径持续存在，规模扩大并没有消除这些具体实现差异。

## 7. 对旧用例代表性的结论

1. **旧 OPM＋TLC 覆盖了相当多的基础原生计算。** 本批大档在 Excel／PDF／Word 中分别覆盖约 92%／87%／72% 的采样周期权重；原来部分低覆盖确实受到小输入下公共开销权重的影响。
2. **不能把所有差额解释为小输入。** PNG 滤波在 Word／PDF 放大后仍明显，PPT 也持续存在大块图像处理实现差异。这些是旧函数清单的实测缺口。旧任务已有图片处理，缺的是这里观察到的具体库函数／子路径。
3. **如果目标是补函数热点，优先补预览 PNG 滤波路径及 PPT 图像发布路径。** 前者在这批 Word／PDF／Excel 中重复出现；后者涉及 ImageMagick 滤波、JPEG 编码、LibreOffice 位图处理等，不能只靠放大旧 OPM／TLC 推定覆盖。这不是本轮已经完成的最小集合优化，也不意味着两条路径覆盖了全部 Word／PPT 操作。

## 8. 来源、重复次数与复核

旧 OPM／TLC 使用既有五次重复的合并函数清单；原始 DocOps 父任务是一次采集内十轮回放。本批各规模各模式均只有一次独立采集，003-u100／037-u5 内含三轮，其余规模一轮。因此本轮能判断已观察到的权重变化，不能估算规模实验的独立重复波动。所有变体均标为合成规模实验，不是新增真实 Agent 轨迹。

读取补符号后 profile，并验证与原始 profile 的样本数、period、DSO 权重守恒。已见／未见／未知三部分以及脚本上下文均守恒；源文件和派生结果摘要见 analysis-build.json。PPT／Excel 既有丢样及 Word lxml 少量未知保持原样，未知未计为未覆盖。
