# 七维 Topdown 新旧用例对照记录

使用七个互不重复的层级前沿指标；度量为完整累计分布的半 L1 百分点差。这是工具累计输出的描述性比较，不是所有 PMU 事件完整有效的声明。

## 结果：Topdown 相似性：从顶层接近到内部瓶颈比较

**本节比较 CPU 的瓶颈分配是否接近，函数与操作是否覆盖仍按 7.3 判断。** 采用七维、不重复计权的分区，替代仅凭四项顶层余弦判相似：同为后端受限，还要区分更偏执行资源还是缓存／内存数据供应。

**表 7-6：七维指标及其读法。** 七项合计约 100%；父项 Bad Speculation、Frontend、Backend 已被下面子项替换，不再重复加入向量。

| 指标组 | 实际进入距离的指标 | 看什么 |
|---|---|---|
| 有效工作 | Retiring（有效完成） | 正常完成指令的流水线份额 |
| 无效执行 | Branch Mispredicts（分支误判）＋Machine Clears（流水线清空） | 误推测的具体构成 |
| 指令供应 | Fetch Latency＋Fetch Bandwidth（前端延迟／带宽受限） | 前端供应问题偏延迟还是吞吐 |
| 执行与数据供应 | Core Bound＋Memory Bound（核心执行／存储受限） | 后端更偏执行资源还是缓存／内存供数 |

**怎么比较：** 主值为七项绝对百分点差之和的一半，即 `D = ½Σ|新值−旧值|`；越小表示分区越接近。例如同为 Backend 70%，一例 Core／Memory 为 60%／10%，另一例为 30%／40%，顶层相同，七维仍能显示 30 pp 的差别。IPC 单独列相对变化，idle 不加入距离。余弦只保留为数据记录中的辅助值。

**“较接近”用什么参照：** 旧 OPM 和 TLC 的七维均值之间距离为 **4.28 pp**。新配置分别与两例比较，取较小距离；不超过这一数值，称为“在旧两场景差异尺度内”，超过则称为“超出旧尺度”。这是本批可解释的参照线，不是通用相似度标准或统计显著性阈值。

**本节结论：哪些接近，哪些存在差异？**

1. **大档中相对较接近的是 013-v1000、026-u10。** 距离分别为 3.78／4.24 pp，落在旧 OPM／TLC 之间的 4.28 pp 尺度内。其中 026-u10 距离接近参照线，应理解为临界接近。原始任务中 009、026，以及小档 026-u5 也落在这一尺度内；这说明部分新操作与旧负载仍共享接近的流水线分配。
2. **其余大档均超出旧尺度，不能统一称为与旧例相似。** 偏离最明显的是 003-u500（19.85 pp）、031-u20（17.15 pp）、037-u20（14.47 pp）；表 7-8 显示它们的执行／存储、前端或有效完成份额发生了具体变化。
3. **函数覆盖提高，不保证 Topdown 更相似。** 例如 014-n10000 的旧函数覆盖约 91.82%，七维距离仍为 11.93 pp；003 从原始到大档也明显偏离。相同函数可以承担不同权重，因此 7.3 的覆盖与本节的分区接近程度要一起看。
4. **旧例有共同计算基础的代表性，但不足以代替所有新增任务的瓶颈分配。** 按操作选补例仍采用 7.3 的方案；Topdown 用来说明补入任务带来的 CPU 行为变化，不单凭一个距离判定任务业务是否已覆盖。

统计取 DevKit 最终 Report-ALL：旧两例为五次独立采集的逐项均值，新配置每种模式一次采集；CPU 0–7 包络未按 PID 裁剪，可能包含同核宿主活动；部分时间点未计数和经验公式复算差异均保留。旧例自身最大离均距离为 OPM 1.96／TLC 0.48 pp，本批新配置均超出相应旧例的自身范围；“较接近”不是重复运行意义上的等价。深层十维暂不作为判据，不把未计数值填零。
