其他 CPU 是整轮减去读写并集与 LibreOffice 的余量，包含退出阶段、测量开销及其他操作，不能与脚本角色名 other 混同；未将全部退出 CPU 归因于某个具体函数。

## 修正原因与证据

- atexit 账本是退出清理前的快照，不能代替进程最终 CPU。HR pid41 的账本为31.3345954秒，monitor 最后记录34.95秒，且写出后仍观察到约3.6秒 CPU。
- 各进程统一使用 monitor CPU，账本总 CPU 仅用于双向交叉核对，取消单边截零的“漏采上限”。
- 执行根进程按实际 Python entry.py 参数识别，排除只在 shell 字符串中提及入口的外层 bash。
- ROI 外进程不计入；ROI 结束后第一次采样不作为区间终值。
- TLC 的增强脚本和 verifier 按实际脚本名分类，原 other 角色不再被错误解释为非读写 CPU。

## 保留限制与归档状态

- 50ms轮询可能漏掉短命进程及退出前最后一段CPU，尚无整体损失上限。
- 单进程监控与 atexit 的差异可能有正有负，不能代表全部采集误差。
- ROI 依据容器时钟锚与毫秒级结束时间，未独立校准边界；生命周期判断仍有轮询误差。
- 每配置一轮，不证明稳定性、行业因果关系或优化收益。
- 读写分子未变，比例下降来自修正分母；未扣除估计的测量开销。
- 原 Retail、TLC、Industry 的 measurement-record.json 与旧索引不一致；本轮未改写它们。TLC另3个非分析输入受宿主权限限制，未独立复读。
- 本轮实际使用的 monitor、ledger、运行摘要和业务验证文件均另存 SHA256 来源索引，可验证重算输入。

读写仍主导这四次执行，约占整轮 CPU 的75.8%–83.5%。不能继续写成四者均处于80%–90%。
