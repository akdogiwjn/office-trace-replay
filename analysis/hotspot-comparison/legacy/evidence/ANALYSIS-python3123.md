# Python 3.12.3 文档场景白盒重测报告

## 1. 测试口径

- 容器：`document-oe`
- Python：`/opt/document-bench/.venv/bin/python3`，3.12.3
- 启动方式：`PATH=/opt/document-bench/.venv/bin:$PATH`
- PDF：P03 单申请人版本，性能/热点采集 10 轮
- XLSX：完整工作簿，性能/热点采集 2 轮
- 原生热点：`perf cycles:u`；PDF 99 Hz，XLSX 49 Hz，DWARF 调用栈
- Python 热点：`py-spy --subprocesses`；PDF 99 Hz，XLSX 49 Hz
- 硬件计数器：`cycles:u/k`、`instructions:u/k`、`task-clock`、上下文切换、迁核、缺页
- 调度：PDF 绑定 CPU 8，XLSX 绑定 CPU 8-11
- 系统调用：`strace -f -c`

业务库版本未变化：openpyxl 3.1.5、pypdf 6.10.0、pdf2image 1.17.0、Pillow 12.2.0、et_xmlfile 2.0.0。

## 2. 总体结论

1. Python 3.11.6 升级到 3.12.3 后，两个场景的四步骤、父子进程、线程模型和业务热点路径都没有变化。
2. XLSX 低扰动运行平均耗时从 255.40 秒降至 243.69 秒，本次环境下快约 4.58%。改善主要出现在 P01、P03 和 P04；P02略慢。
3. PDF 单份版从 2.183 秒变为 2.241 秒，慢约 2.66%。场景只有约 2.2 秒，启动和采集抖动占比较高，不能据此认定 Python 3.12 存在稳定退化。
4. XLSX 的 Python/LibreOffice CPU 周期比例几乎不变：Python 92.65%→92.52%，LibreOffice及其线程 7.34%→7.47%。
5. XLSX 的活跃时间仍约 98.31% 为单任务运行，多任务阶段约 1.69%，峰值并行度 4；与旧数据 98.38%/1.62% 基本一致。
6. 系统调用结构没有异常变化。XLSX 两轮总调用数 555,991→556,023，几乎完全相同，仍以 LibreOffice 的 `futex` 同步为主。

注意：旧、新 recipe SHA-256 不同，3.12.3 也是 `/opt` 下的自编译解释器。因此上述耗时变化是“当前新运行环境”的实测结果，不能全部归因于 Python 3.12 本身。

## 3. 四步骤耗时

### PDF 单份版

以下为低扰动运行平均值，均为 10 轮：

| 步骤 | Python 3.11.6 | Python 3.12.3 | 变化 |
|---|---:|---:|---:|
| P01 检查与准备 | 0.892 s | 0.910 s | +2.1% |
| P02 构建输入 | 0.060 s | 0.052 s | -12.2% |
| P03 单份填写与渲染 | 0.924 s | 0.953 s | +3.1% |
| P04 验证交付 | 0.305 s | 0.323 s | +5.8% |
| 整轮 | 2.183 s | 2.241 s | +2.66% |

PDF 的绝对差值仅约 58 ms，并且 recipe 版本不同，应视为小幅波动，不宜解释为确定的版本退化。

### XLSX

以下均为 2 轮平均值：

| 步骤 | Python 3.11.6 | Python 3.12.3 | 变化 |
|---|---:|---:|---:|
| P01 检查与准备 | 59.426 s | 56.526 s | -4.9% |
| P02 构建增强 | 52.584 s | 53.499 s | +1.7% |
| P03 重算与发布 | 93.688 s | 87.965 s | -6.1% |
| P04 验证交付 | 49.697 s | 45.698 s | -8.0% |

## 4. 进程与动态库热点

### PDF

| 进程/动态库 | 3.11.6 | 3.12.3 |
|---|---:|---:|
| 全部 `python3` 进程 | 91.02% | 90.64% |
| `pdftoppm` | 8.93% | 9.23% |
| `libpython` | 56.39% | 53.58% |
| zlib | 17.06% | 18.14% |
| Pillow `_imaging` | 15.00% | 15.21% |
| Poppler | 4.69% | 6.27% |
| FreeType | 2.57% | 1.88% |

PDF 原生数据只有约 2,000 个样本，1 个百分点左右的变化可能包含采样误差。结构性结论不变：Python 主导，`pdftoppm` 仍需作为独立地址空间分析。

### XLSX

| 进程/动态库 | 3.11.6 | 3.12.3 |
|---|---:|---:|
| 全部 `python3` 进程 | 92.65% | 92.52% |
| LibreOffice及其线程 | 7.34% | 7.47% |
| `libpython` | 79.61% | 79.65% |
| Expat XML 解析 | 6.42% | 5.61% |
| `_elementtree` | 3.40% | 3.49% |
| zlib | 1.41% | 1.42% |

3.12 中 Expat 体现为 `pyexpat.cpython-312-...so`，旧环境体现为 `libexpat.so`，属于打包/链接呈现变化，业务仍是 XML 解析热点。

XLSX 原生数据记录 81,106 个样本，丢失 659 个样本，约 0.8%；适合判断热点排序和近似占比，不适合解释小数点后微小差异。

## 6. 用户态、内核态与 IPC

| 场景 | 模式 | 指令占比 | 周期占比 | CPU时间占比 | IPC |
|---|---|---:|---:|---:|---:|
| PDF单份版 | 用户态 | 93.07% | 86.07% | 86.79% | 2.55 |
| PDF单份版 | 内核态 | 6.93% | 13.93% | 13.21% | 1.17 |
| XLSX | 用户态 | 99.24% | 97.83% | 98.12% | 2.53 |
| XLSX | 内核态 | 0.76% | 2.17% | 1.88% | 0.87 |

PDF 旧硬件计数器数据来自 P03 处理 10 份的版本，不能与当前单份版直接比较。当前单份版中固定的进程启动和文件操作占比更高，因此内核态比例自然高于 10 份版。

XLSX 与旧数据非常接近：用户态周期 98.01%→97.83%，用户态 IPC 2.57→2.53，没有发生执行模式变化。

## 7. 调度与并行度

### PDF（绑定 1 核）

- 活跃时间单任务占比：100%
- 多任务运行：0%
- 峰值并行度：1
- 结论：仍是多个父子进程串行接力，不是同时并行执行。

### XLSX（绑定 4 核）

| 指标 | 3.11.6 | 3.12.3 |
|---|---:|---:|
| 活跃时间单任务占比 | 98.3784% | 98.3111% |
| 活跃时间多任务占比 | 1.6216% | 1.6889% |
| 峰值并行度 | 4 | 4 |
| 整段平均并行度 | 0.99986 | 0.99851 |

结论：XLSX 仍是“长时间单任务 + LibreOffice 短暂多线程”的模型，Python 版本没有改变并行结构。

## 8. 上下文切换与系统调用

XLSX 两轮低扰动计数：

| 指标 | 3.11.6 | 3.12.3 | 变化 |
|---|---:|---:|---:|
| 上下文切换 | 57,011 | 56,844 | -0.29% |
| CPU迁移 | 11,302 | 11,270 | -0.28% |
| 缺页 | 4,500,341 | 4,357,358 | -3.18% |

XLSX 两轮 `strace -f -c`：

| 指标 | 3.11.6 | 3.12.3 |
|---|---:|---:|
| 系统调用总数 | 555,991 | 556,023 |
| `futex` 调用 | 110,379 | 111,894 |
| `futex` 跟踪时间占比 | 78.57% | 79.87% |

系统调用数量基本不变。`strace` 的时间占比受跟踪开销和阻塞等待影响，不等于 CPU 内核态比例；准确的内核态 CPU 结论以第 6 节为准。

PDF 当前单份版 10 轮共 733,955 次系统调用，以 `wait4` 等待串行子进程为主要跟踪时间；旧 PDF 系统调用数据属于不同的申请人数口径，不做数值对比。

## 9. 对切片与插桩的影响

- 原来的插桩位置和单进程切片划分可以继续使用。
- PDF 仍需分别覆盖 Python 脚本进程和实际 `pdftoppm` 进程。
- XLSX 仍需分别覆盖各 Python 进程和实际 LibreOffice 进程；LibreOffice线程随 `soffice.bin` 一起采集。
- 原有切片权重应更新为本次 Python 3.12 数据，不能继续使用 3.11 的精确百分比。
- 原生符号过滤应从 `libpython3.11.so` 更新为 `libpython3.12.so`，Python 扩展模块后缀也从 `cpython-311` 更新为 `cpython-312`。
